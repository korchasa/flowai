# Task: Finish the Session

## Overview

Closes a working session in one invocation: it proves that the session's goals are met, puts the work on the remote, and archives the session.

1. **Goals Phase** — every goal of the session checked against evidence gathered now, with one verdict line.
2. **Commit Phase** — targeted documentation sync + Conventional Commits + task-status auto-flip.
3. **Push Phase** — safe `git push` with upstream and divergence gates.
4. **Archive Phase** — final report, then the session is archived with the host's own means.

Three explicit gates between phases:

- **Goals → Commit** — the verdict MUST be `Goals: all met`. A goal that is not met or not verified → STOP. The per-goal report reaches the user in the final report, or in the STOP message.
- **Commit → Push** — every change of this session MUST be committed.
- **Push → Archive** — the push report does NOT end the run; the work MUST be on the remote before the session is archived.

## Context

<context>
Finishing a session by hand is four separate acts, and the first one — checking that what was asked for exists — is the one that gets skipped. This composite makes it the entrance: nothing is committed for a session whose goals do not hold. There is no review phase and no reflection phase; a user who wants the diff reviewed before the commit asks for that workflow instead. Archiving is the only step that depends on the host: some hosts give the agent a tool that archives its own session and may remove the session's working copy with it, others give nothing. ## Rules & Constraints

<rules>
1. **No skill re-entry**: All four phases are FULLY INLINED below. Execute the steps directly. Do NOT invoke any goal-check, commit or push skill via the Skill tool — it would re-enter without the composite's gate logic and the workflow would silently exit between phases.
2. **Four Phases, Strict Order**: Goals, then Commit, then Push, then Archive. Never interleave; never skip a gate.
3. **The user sees the goal report in full**: the verdict line and every goal with its status and evidence. On a STOP at the Goals Gate it is the last thing you write. On a run that goes on, the final report of the Archive Phase carries it in full — a bare `Goals: all met` there is not the report.
4. **Goals Gate**: only `Goals: all met` proceeds. Any goal `not met` or `not verified` → STOP. Do NOT repair an unmet goal inside this run to get past the gate: finishing work is a new request, and the user decides whether to make it.
5. **A STOP ends the run**: after a STOP no later phase runs — no commit, no push, no archive. Report which gate stopped you and why, then hand control back to the user and wait.
6. **Nothing to commit is not a failure**: when the session changed no file, the Commit Phase reports "Nothing to commit". Treat that report as a completed Commit Phase and continue with the gate after it.
7. **Archive is the last act**: nothing is written, run or edited after the session is archived. Never imitate archiving by deleting or moving transcripts, branches, worktrees or project files.
8. **Session Scope**: compare current `git status` with the git status snapshot from session start (available in system context). Files already modified/untracked at session start are outside the commit scope — note them but do not commit them. If unsure which changes are yours, ask the user before staging.
9. **Planning**: use a task management tool (e.g. `todo_write`, `todowrite`, `Task`) to track all four phases as a single plan.
</rules>

<gate after="1">
### Goals → Commit Gate

Read the verdict line of the goal report from the Goals Phase:
- `Goals: all met` → continue in this same turn with the Commit Phase below. Keep the report: the Archive Phase sends it in full.
- `Goals: none found in this session` → there is nothing to verify. Say so in one line and continue with the Commit Phase below.
- `Goals: NOT all met` → write the full goal report to the user and **STOP**. Do NOT commit, push or archive, and do NOT start fixing the unmet goal. End with one line: which goals block the finish, and that the user can ask to finish them or to close the session as it is.
- The user replies that the session should be closed as it is → that is a new instruction from the user and it opens the gate: continue with the Commit Phase and name the unmet goals again in the final report.
</gate>

<gate after="2">
### Commit → Push Gate

- Run `git status --porcelain`. Every file this session created or modified MUST be committed. One of them still listed → **STOP** and name it.
- Files that were already modified or untracked at session start (rule 8) do not stop the push: they are not this session's work. List them — the Archive Phase asks about them.
- The branch has no upstream and nothing to push to (`git remote` prints nothing) → skip the Push Phase, say so in one line, and continue with the Archive Phase.
- Otherwise → enter the Push Phase. If the user declines the push at its first-push or divergence gate, **STOP** — the commits stay local, and a session with unpushed work is not archived.
</gate>

<gate after="3">
### Push → Archive Gate

- The push report is not the end of the run. The next phase here is the Archive Phase below; it runs in this same turn, without waiting for the user to ask for it.
- You are only here if the push succeeded and `git rev-parse @{u}` equals `HEAD`, or the Push Phase was skipped because the repository has no remote. A failed push, a CI failure handed to an investigation, or a CI anomaly is a STOP (rule 5) and never arrives here.
</gate>

<inline-phase index="4">
### Archive Phase

1. **Send the final report first**
   - Archiving can end the conversation, so the report goes out before it:
     - **Goals**: the goal report from the Goals Phase in full — the verdict line, then one entry per goal with its status and the evidence you observed (the command and its result, or the file). A verdict line alone is not enough: this is where the user sees what was checked. Name any goal the user chose to leave unmet.
     - **Commit**: the commits made, or "nothing to commit".
     - **Push**: branch, upstream, pushed SHA, or why there was no push.

2. **Check what would be lost**
   - Run `git status --porcelain`. On some hosts archiving a session also removes its working copy, and uncommitted files go with it.
   - The output is empty → continue with step 3.
   - Files are listed → name them and ask once: "These files are not committed and may be removed together with the session. Archive anyway?" Wait for the reply. A refusal → say that the session stays open and **STOP**.

3. **Archive the session with the host's own means**
   - Look at the tools you have in this session for one that archives or closes the CURRENT session (e.g. a session-archive tool in the Claude desktop app). Decide from the tool list alone; do not search the file system for a way.
   - Such a tool exists → call it for the current session. The invocation of this workflow is the user's request to archive; if the host asks the user for its own approval, that is the host's step, not yours. This call is the last action of the run — write nothing after it. If the host refuses or the user declines the approval, say so in one line and stop.
   - No such tool → say in one line that this host gives you no way to archive the session from inside it, and that the user can archive or close it in the host's interface. Then stop.
   - Never substitute something else for it: do NOT delete or move session transcripts, do NOT remove branches or worktrees, do NOT clear the conversation.
</inline-phase>
